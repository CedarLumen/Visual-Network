# 界面多语言：文案怎么加、怎么改

界面与核心里的用户可见文案都写成 `core::tr("中文", "English")`：

- **中文那一份就是原文**，必须保持逐字不变。离线断言、命令行输出与 `说明.md` 都是按中文写的，
  改中文等于改断言（`src/tests/test_lang.cpp` 里钉了几条）。
- **英文那一份只在切到英文时使用**；默认是中文。
- 语言只影响「给用户看的字」，不影响任何计算、存取格式或行为。

## 目录里的东西

| 文件 | 说明 |
| --- | --- |
| `list_*.txt` | 清点结果：源码里带中文的字面量（`# 路径` 开头的是文件标记） |
| `tr_*.tsv` | 中英对照表：`中文<TAB>English`，与同名清单逐行同序（共 473 条） |
| `../i18n_apply.py` | 落地工具：清点 / 生成对照表 / 包装进源码 / 检查漏网 |
| `../i18n_verify.py` | 独立校验：行数、中文列逐字节、英文列不含中文 |

## 加一条新文案

1. 直接在源码里写 `core::tr("中文", "English")`（两边都要给），**不用**动对照表。
   在 `ui/`、`gfx/`、`gpu/`、`main.cpp` 里要写 `core::tr(...)`；在 `core/` 命名空间里写 `tr(...)`。
2. 长句拆成多段字面量时（`"前半" "后半"`），整段只包一个 `tr()`，中英各写成同样的一段，
   别写成两个 `tr()` 并排（那样语法不成立）。
3. 只需要一个标点或符号时也给两份写法：`tr("（", " (")`、`tr("、", ", ")`、`tr("」", "\"")`。
4. Win32 里必须用宽字符的地方（例如窗口标题）用 `core::trw(L"...", L"...")`。

## 检查有没有漏翻译

```
python tools\i18n_apply.py --help
```

按 `list_*.txt` 重新 `apply` 是幂等的（已经包过的会跳过）。新增文案后想确认没漏，可以重新清点一次，
把「带中文但没被 tr() 包住」的字面量列出来逐条看：

- `src/core/Names.cpp` 是**允许项**：里面的中文是默认模块名/组名本身（存进图里的数据），
  由 `core::displayName()` 在显示时按语言映射。
- `src/tests/`、`src/cli.cpp` 不参与界面多语言（断言与命令行输出固定用中文）。
- 界面上的 `－` `＋` 是符号，不是词，两种语言下都长这样。

## 已知边界

- 用户在英文界面下**自己起的中文名字**（模块名、组名）在中文界面下也原样显示：名字是数据，
  不是界面文案。
- 界面自动生成的组名固定用「存档用的类型名 + 组合」（与界面语言无关），显示时再按语言映射，
  这样同一份存档在两种语言下都能读。
