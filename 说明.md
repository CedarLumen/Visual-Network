# Neural Network Simulation Engine (Windows)

A desktop tool for building, editing, and running neural network structures directly. The engine is implemented from scratch and does not rely on any inference framework: convolution, pooling, fully connected layers, and activation functions are computed by this project's own operator layer; rendering uses a self-written OpenGL 3.3 renderer; lower-level computation can be accelerated with CUDA. The application includes real handwritten digit samples and a trained example network; it can perform recognition immediately after launch.

- Program name: `Neural Network Simulation Engine` (`nne.exe`, window 1360×880)
- Runtime environment: Windows 10/11 x64; CUDA acceleration is enabled when the graphics driver is NVIDIA.
- Accuracy of the example network on the 10,000-image MNIST test set: **98.07% (9807/10000)**
- Third-party dependencies: none. Only system-provided `opengl32` / `gdi32` / `user32` and the CUDA runtime library are used.

## 1. Interface

The top two rows are reserved for the top bar and toolbar; the rest is the canvas. No buttons are placed on the left.

| Location | Content |
| --- | --- |
| Top bar | Row 1: structure validation result, module count, parameter count; Row 2: operation receipt (left) and loop status (fixed position on the right); zoom ratio is to the left of "Fit View". Variable text occupies separate positions and does not push against other text, so readings do not jitter. |
| Toolbar | Module Library / Run Loop / Auto Arrange / Example Network |
| Canvas | Modules are rectangles; the dots inside a rectangle represent the small neurons composing it; the input layer is drawn directly as the 28×28 pixel image of the current sample digit. |
| Right side | Parameter area for the selected module (adjustable with plus/minus) and operation buttons; fixed width; the canvas does not shift when a module is selected. |

Long text (structure overview, operation receipts, evaluation conclusions, help pages) wraps automatically to the panel width and is clipped within its own area; it does not overflow the panel or cover adjacent controls.

The interface font size and layout are controlled by a single scale parameter (`UI_SCALE` in `src/ui/ui.h`, currently 1.25, i.e., one step larger than the initial version). Font size, line spacing, button height, and panel width all scale with it. Changing one value adjusts the whole interface up or down without text being covered by buttons.

There is also a hidden hint below the canvas: hovering over the description on the right side of the top bar reveals the current mouse operation mode (see Section 2).

| Middle- or right-drag | Pan the canvas. |
| Space + drag | Pan the canvas (for notebooks without a middle button). |

### Batch Operations

After selecting multiple modules, the buttons on the right apply to all selected items:

- **Parameter increment/decrement**: modify all selected items simultaneously (for example, increase the kernel count of two convolution layers at once).
- **Duplicate**: duplicate the whole selection (offset placement; connections are not copied).
- **Delete**: delete the whole selection and automatically connect the upstream and downstream of the deleted segment.
- **Group / Ungroup**: merge several modules into a semi-finished module; a named group box appears on the canvas.

After each operation, the top bar displays a receipt, for example "Duplicated 7 modules."

### Neurons (Inside a Module)

After selecting a module, click "View Neurons" to enter the internal view; double-clicking a module also enters it. A module consists of several small neurons:

| Module | Meaning of Neuron | Add/Remove |
| --- | --- | --- |
| Input layer | One neuron per pixel; displays the current sample digit. | No; change input size instead. |
| Convolution layer | Each neuron is a set of convolution kernels (one output channel). | Can delete; deleting reduces the number of channels. |
| Pooling layer | Each neuron corresponds to one channel. | No; follows the upstream channel count. |
| Flatten layer | Flatten to one dimension. | No. |
| Fully connected layer | Each neuron is a hidden unit. | Can delete. |
| Output layer | Each neuron is a class. | Can delete; at least 2 classes remain. |

In the internal view, you can click or box-select neurons, then click "Delete Selected Neurons" to delete them in batch.

## 3. Run Loop (Forward Inference and Weight Update in the Same Loop)

The "Run Loop" button on the toolbar opens the only run panel: forward inference and training share the same loop; the only difference is the "Update Weights" option.

| Control | Description |
| --- | --- |
| Start / Pause | Toggle for the same loop. After starting, each step performs one forward pass and is counted in statistics; after pausing, the step count stops immediately. |
| Single Step | Advance one step while paused; if the loop is running, a prompt asks you to pause first. |
| Clear Statistics | Reset step count, average reward, and reward curve from this step. |
| Reset Neural Network | Restore weights to their initial values (or to the pretrained parameters if present); clear training archive, reward curve, and statistics together; structure and formulas remain unchanged. |
| Update Weights | On = each step performs one backpropagation step according to the learning rate; the step is training. Off = only forward pass; weights do not change at all. |
| Learning Rate | 0.001–1; − halves / + doubles, with lower-bound protection. |
| Loop Frequency | 1–5000 steps/s. Can be adjusted with −/+, or entered directly in "Frequency Direct Input"; when above 20 steps/s, the panel shows a hint. |
| Reward Curve | Scores of the most recent 200 steps, with reference lines for 0 and full score. |

One step performs: the input function provides the input for this layer → one forward pass → the output function determines the final output → (if a target component exists) the target function provides the expected output, and loss and score are computed → if "Update Weights" is on, backpropagation is performed and weights are updated according to the learning rate.

The panel shows the current step directly:

- The top states which set of weights this step uses (bundled pretrained parameters / generated by structure / updated each step by learning rate), and whether this step "updated weights by learning rate" or "only performed forward pass."
- The heatmap on the left shows the current layer's activations: feature maps are laid out by channel; one-dimensional layers are drawn as bars by value.
- "Previous Layer / Next Layer" switches the layer to view and displays that layer's input/output sizes and time cost.
- The right side shows the original image of the current sample digit, the true digit, and the network's decision; the line below gives output probabilities, expected output, loss, and reward.
- "Previous Example / Next Example" switches among the 20 bundled handwritten digits; while the loop is running, this cell is advanced by the loop itself, and the heatmap and preview are always the same image.
- "Evaluate All Examples" runs all 20 samples and gives the number of correct recognitions and total time; after a structural change, this conclusion is cleared.

**Difference between "Look Once" and "Advance One Step"**: the automatic forward pass after opening the panel, switching examples, or changing the structure is only a preview (the panel states "Preview forward: does not change weights and is not counted in statistics"). It neither changes weights nor enters statistics or the reward curve; only each loop step and "Single Step" are counted in statistics and the reward curve.

Below these buttons are two compute-related items:

| Location | Content |
| --- | --- |
| "GPU Acceleration: On / Off" | Whether batch evaluation uses the GPU or CPU one-by-one. Click to toggle; the top bar shows a receipt; after turning it off, "Evaluate All Examples" runs on the CPU one by one. |
| "Compute Backend:" | The backend actually in use, for example "CUDA · NVIDIA GeForce RTX 5060 Laptop GPU"; if no device is available, the reason is stated. |

The conclusion of "Evaluate All Examples" also states which backend computed this batch and the time taken (for example, "Correct 20/20, total 6.9 ms  ·  Compute backend CUDA · NVIDIA GeForce RTX 5060 Laptop GPU (batch computed at once)"). The decisions from the two paths are completely identical; switching backends does not change recognition results.

There are three sources of parameters: when the structure is exactly the same as the bundled example network, pretrained parameters are used; after the main chain structure changes (for example, a new layer is connected into the main chain), deterministic random weights generated from the structure fingerprint are used, and the result page states "Structure differs from the example network; weights generated by structure; forward computation only"; when the graph contains self-generated input or target-output reward, trainable weights are used, with the note "Using current weights (this step performs forward only)" or "Updating weights each step at learning rate 0.05."

When the graph contains self-generated input or target-output reward, the example row changes to show this step's **input, network output, and expected output**; "Evaluate All Examples" correspondingly changes to **100 random input groups not yet trained**'s average score, average loss, and hit count.

After all modules on the canvas are deleted, the heatmap and layer-by-layer view show "No runnable layers on the canvas"; "Previous Layer / Next Layer" no longer takes values; the loop stops automatically; single-step and batch evaluation do not execute, and a receipt is shown in the top bar.

## 4. Trainable Task Graph and Training

Place the "Self-Generated Input" and "Target Output Reward" components on the canvas to turn the chain into a trainable task graph. When neither component is in the graph, "Update Weights" has no effect; the panel states "The current structure has no trainable layers," and the loop performs forward inference only.

| Component | Function |
| --- | --- |
| Self-generated input | Generates the input values for this layer itself; the count is adjustable. It has a fixed seed; the same structure produces the same set of numbers each time it is opened, and step N takes the Nth group. After selecting it, the right side has "Re-randomize," which changes the input values without changing trained weights. |
| Target output reward | Computes this step's **expected output** from the current input (given by the target function), and provides loss, mean absolute error, and score. It is also the starting point for backpropagation; the output count is adjustable. |

The "Custom Functions" button expands four formulas (input, output, reward, target), see Section 6.

Training results (weights and random seed) are stored in application settings by **structure fingerprint**; training continues on the next launch. Once the structure changes, the old archive is automatically invalidated, and weights with mismatched sizes are not forcibly applied.

## 7. Custom Functions

The input, output, reward, and target formulas use the same small expression language. Its lexer, parser, and evaluator are implemented in this project, without any dynamic evaluation capability, so it can be compared item by item offline.

| Function | Number of Calls per Step | Default Formula | Meaning of Default Formula |
| --- | --- | --- | --- |
| Input function | Once per input layer position | `px/255` | Directly uses the original pixels of the bundled handwritten digit as input. |
| Output function | Once per output unit | `v` | Directly uses the network output value. |
| Reward function | Once at the end of each step | `score` | Uses the computed score (1 minus mean squared error when a target component exists; 0/1 correctness otherwise). |
| Target function | Once per output unit | `sin(3*in(0))` | Expected output = sine of the current input, a fitting task with visible convergence. |

Common variables:

- Position and size: `c` `y` `x` `i`, `h` `w` `ch` `n`
- Normalized coordinates: `u` `v` `cx` `cy` `rr` (top-left is 0, center is 0 or 1, `rr` is distance to center)
- Original value of this layer: `px` (handwritten digit input is 0–255 pixels; self-generated input is a random value from -1 to 1)
- Input vector: `in(k)` and `nin`
- Network output and decision: `v` `pred` `top` `p` `sum` `mean` `hit`
- Difference from expected output: `loss` (mean squared error), `mae` (mean absolute error), `score` (= 1 minus mean squared error)
- Progress: `t` step count, `k` example index, `count` example count, `label` true digit

Operators and built-in functions: `+ - * / %`, comparisons, `&& || !`, ternary `cond ? a : b`, and `sin cos tan sqrt abs floor ceil round min max pow exp log clamp lerp step sign sigmoid relu`, etc.; the "Syntax and Function Table" lists all entries.

If a formula cannot be parsed, the program does not stop; that item falls back to its default formula, and the panel states the reason (for example, "Target function cannot be parsed; this step is computed with the default formula sin(3*in(0))").

## 8. Compute Backend and CUDA Acceleration

The engine's operators have two equivalent implementations: a CPU reference implementation (`src/core/Ops.cpp`) and a CUDA implementation (`src/gpu/`).

- CUDA is used by default when an available NVIDIA device is present; on another machine or a machine without a GPU, it automatically falls back to CPU.
- **Batch computation uses the GPU**: multiple samples are concatenated into one large feature map by "channel = sample," and the entire batch is computed at once, continuously performing "convolution → activation → pooling → convolution → activation → pooling → flatten → fully connected → Softmax." "Evaluate All Examples" and the command-line `--mnist gpu` both use this path.
- **The interface shows and can switch the backend**: the run loop panel has a "GPU Acceleration: On / Off" button, with the current backend shown on the right (for example, "CUDA · NVIDIA GeForce RTX 5060 Laptop GPU"); after turning it off, "Evaluate All Examples" runs on the CPU one by one. The recognition conclusions from both backends are completely identical. The evaluation conclusion line states which backend computed this batch and the time taken.
- **Layer-by-layer forward and training are faster on CPU**: each step for a single sample takes only a few microseconds; one GPU kernel launch itself costs more than that, so layer-by-layer heatmap display and each step of the loop are still computed by the CPU, preventing the interface from stuttering due to a kernel launch.
- The CUDA implementation and the CPU reference implementation were compared at the **bitwise-identical** level: convolution, pooling, fully connected, backpropagation, and all batch operators relative to per-sample calls. The measured maximum difference is **0**. For paths involving `exp` (Sigmoid / Tanh / Softmax), affected by the last 1 ulp of the device library and MSVC library, the measured maximum difference is 1.73e-18.
- There is also a "Fast float" mode: measured maximum difference 6.34e-07 for a single layer and 2.34e-06 for the whole network (10,000 samples); suitable for scenarios where only the conclusion matters.

Measured (RTX 5060 Laptop, 10,000 MNIST test images, produced in one run of `nne_cli --mnist both`):

| Path | Time | Throughput | Relative to CPU one-by-one |
| --- | --- | --- | --- |
| CPU one-by-one (`core::runGraph`) | 2888.1 ms | 3462 images/s | 1× |
| CUDA batch (double precision, 8 kernels) | 1058.8 ms | 9445 images/s | 2.73× |
| CUDA batch (fast float, measured in suite G-gpu) | 396.2 ms | 25241 images/s | 6.58× |

The two paths made completely identical decisions on these 10,000 images (9807/9807, 0 disagreements). In the same batch of data, batch processing is about **50×** faster than a single-sample loop that sends one image at a time to the GPU: each layer in the single-sample case requires two host-device transfers, while the batch transfers once.

Timing fluctuates with machine load (the same operation measured at different times can differ by up to 2×); the table above is a pair of values taken within the same minute, for magnitude reference.

## 11. Build and Run

Requires Visual Studio 2022 (with Desktop development with C++) and CUDA Toolkit. The easiest way:

```powershell
powershell -File tools\build.ps1
```

It uses VS's bundled CMake to configure and build Release; artifacts are in `D:\NNE-win-build\Release\`: `nne.exe` (double-click to use), `nne_cli.exe`, `nne_tests.exe`.

When configuring manually, specify the CUDA architecture according to the GPU architecture (this machine is RTX 50 series, `sm_120`):

```powershell
cmake -S . -B D:\NNE-win-build -G "Visual Studio 17 2022" -A x64 -DCMAKE_CUDA_ARCHITECTURES=120
cmake --build D:\NNE-win-build --config Release --parallel
```

On a machine without a GPU, add `-DNNE_WITH_CUDA=OFF`: CUDA language is not enabled, CUDA Toolkit is not searched, and only the CPU path is built (host-side code in `src/gpu/` except `.cu`). This configuration was measured to build all three exes completely; `nne_tests.exe G-gpu` has 369 assertions all green, and `Z MNIST full evaluation` has 62 assertions all green, all computed on CPU. The backend description is truthfully written as "CPU (CUDA backend not included in this build)," and the backend indicator in the interface follows the same wording.

Archives are written to `%APPDATA%\NeuralNetworkEngine\` (structure, formulas, and training results each in one file); deleting them restores factory state.

## 13. Known Boundaries

- A graph supports only one input layer and one output layer; data flow is a single main chain (a module may have multiple upstreams, but only one outgoing connection).
- Execution is sequential; no multi-branch parallelism. Each loop step performs one forward pass (using pretrained parameters or current training weights); when "Update Weights" is on, that step also performs backpropagation according to the learning rate. Training is per-sample stochastic gradient descent, not mini-batch.
- Modules not connected to the data flow do not participate in computation; the status bar shows a hint. After being connected to the main chain (or after clicking "Auto Arrange"), they participate in computation.
- Connections are **one in, one out**: connecting a layer to a new target simultaneously disconnects its original outgoing line and the target's original incoming line, so rewiring requires only reconnecting once; parts that cannot be reconnected after disconnection can be rearranged left-to-right by clicking "Auto Arrange."
- The channel count of a pooling layer follows its upstream and cannot be added or removed independently.
- Training and layer-by-layer forward passes are computed on the CPU; batch evaluation is computed on the GPU. The layer-by-layer heatmap is a single forward pass; the cost of one GPU kernel launch exceeds these few microseconds of computation, so it does not use the GPU.
- Canvas placement is automatically remembered and reused on next launch; "Example Network" restores the initial structure.
- The loop frequency upper limit of 5000 steps/s is for "full-speed running": a single step is about 10 ms, and the actual maximum is about 100 steps/s; entering a larger value only means it no longer waits, not that it runs faster. When the frequency is above 20 steps/s, the panel shows a hint.
- The module library is ordered "examples first, components after"; the three examples are at the top and can be clicked without scrolling first.
- Training results are saved by structure fingerprint and become invalid once the structure changes; for a clean starting point, click "Reset Neural Network."
- After all modules on the canvas are deleted, the panel shows "No runnable layers on the canvas," and the layer-by-layer view no longer takes values; the experiment loop stops automatically, single-step and batch evaluation do not execute, and a receipt is shown. Click "Example Network" to restore the initial structure.
- Headless self-check (`nne_cli.exe --selftest`) currently has **all 96 assertions passing**, and two consecutive runs produce identical results.
- The interface language (Chinese / English) is switched by the button on the right side of the top bar; the choice is recorded in `lang.txt` in the application data directory. The Chinese version is the original and the default, so the Chinese text and assertions are unchanged word for word; the English comparison table is in `tools/i18n/` (inventory list + Chinese-English comparison, 473 entries total). When adding new text, follow the process in `tools/i18n/README.md`.
- Module names and group names are **data stored in the graph** (the bundled examples are named things like "Convolution Layer," and users can rename them); switching languages does not modify the archive: bundled default names are displayed in the current language, while user-created names are displayed as-is (see `src/core/Names.h`). It uses its own archive directory (`tools\out\selftest-data`, cleared before each run), so it is neither affected by a training graph left over from a previous run nor writes to `%APPDATA%`; the exit code of `tools\verify.ps1` is therefore 0.

## 三、运行循环（前向推理与权重更新共用同一循环）

工具栏中的「运行循环」用于打开运行面板。前向推理与训练共用同一循环，区别仅在于是否开启「更新权重」。

| 控件 | 说明 |
| --- | --- |
| 开始 / 暂停 | 控制同一循环的启动与暂停。启动后每一步执行一次前向并计入统计；暂停后步数立即停止 |
| 单步 | 暂停状态下执行一步；循环运行中会提示先暂停 |
| 统计清零 | 清除步数、平均奖励与奖励曲线，并从当前步重新统计 |
| 重置神经网络 | 将权重恢复为初始值（存在预训练参数时恢复至预训练参数），同时清空训练存档、奖励曲线与统计；结构与公式保持不变 |
| 更新权重 | 开启时，每步按学习率执行一次反向传播，该步属于训练；关闭时仅执行前向，权重不更新 |
| 学习率 | 0.001～1，－ 减半 / ＋ 加倍，带下限保护 |
| 循环频率 | 1～5000 步/秒。可通过 －/＋ 调整，也可在「频率直接填」中输入数值；高于 20 步/秒时面板显示提示 |
| 奖励曲线 | 显示最近 200 步得分，并绘制 0 分与满分参考线 |

每一步执行流程如下：输入函数给出该层输入；执行一次前向；输出函数确定最终输出；存在目标元件时，由目标函数给出期望输出并计算损失与得分；若开启「更新权重」，则执行反向传播并按学习率更新。

面板显示当前步信息：

- 顶部注明当前步使用的权重来源（自带预训练参数 / 按结构生成 / 每步按学习率更新），以及当前步是「按学习率更新了权重」还是「只做前向」
- 左侧热力图显示当前层激活：特征图按通道铺开，一维层按数值绘制柱状图
- 「上一层／下一层」切换查看层，并显示该层输入输出尺寸与耗时
- 右侧显示当前示例数字原图、真实数字与网络判定；下方显示输出概率、期望输出、损失与奖励
- 「上一个示例／下一个示例」切换自带的 20 个手写数字；循环运行时该位置由循环自动推进，热力图与预览始终为同一张图
- 「评估全部示例」运行全部 20 个样本，给出识别正确数与总耗时；结构改动后该结论清空

**「看一次」与「走一拍」的区别**：打开面板、切换示例或结构改动后自动执行的前向仅用于预览（面板注明「预览前向：不改权重，也不计入统计」），不更新权重，也不计入统计与奖励曲线；只有循环的每一步与「单步」才计入统计与奖励曲线。

上述按钮下方还有两项与算力相关的设置：

| 位置 | 内容 |
| --- | --- |
| 「显卡加速：开 / 关」 | 控制批量评估使用显卡或 CPU 逐张计算。单击即可切换，顶栏显示回执；关闭后，「评估全部示例」改为在 CPU 上逐张计算 |
| 「计算后端：」 | 显示当前实际后端，例如「CUDA · NVIDIA GeForce RTX 5060 Laptop GPU」；无可用设备时注明原因 |

「评估全部示例」的结论中会注明本批计算所用后端与耗时，例如「识别正确 20/20，合计 6.9 ms  ·  计算后端 CUDA · NVIDIA GeForce RTX 5060 Laptop GPU（批量一次算完）」。两种后端的判定结论完全一致，切换后端不会改变识别结果。

参数来源分为三种：结构与自带示例网络完全一致时，使用预训练参数；主链结构发生变化（例如将新层接入主链）后，改用按结构指纹生成的确定性随机权重，结果页显示「结构与示例网络不一致，权重按结构生成，只做前向计算」；图中包含自生成输入或目标输出奖励时，使用可训练权重，并显示「使用当前权重（这一步只做前向）」或「每步按学习率 0.05 更新权重」。

图中包含自生成输入或目标输出奖励时，示例行改为显示当前步的**输入、网络输出与期望输出**；「评估全部示例」相应改为**未训练随机输入 100 组**的平均得分、平均损失与命中数。

画布模块全部删除后，热力图与逐层视图显示「画布上没有可运行的层」，「上一层／下一层」不再取值，循环自动停止，单步与批量评估不执行，并在顶栏给出回执。

## 四、可训练的任务图与训练

将「自生成输入」与「目标输出奖励」两个元件放入画布后，该链路成为可训练任务图。若图中不包含这两类元件，「更新权重」不生效，面板显示「当前结构没有可训练的层」，循环仅执行前向推理。

| 元件 | 作用 |
| --- | --- |
| 自生成输入 | 自行产生该层输入值，个数可调；带固定种子，同一结构每次打开得到同一组数，第 N 步取第 N 组。选中后右侧提供「重新随机」，可更换一组输入值，已训练权重不变 |
| 目标输出奖励 | 按当前输入计算该步的**期望输出**（由目标函数给出），给出损失、平均绝对误差与得分；同时作为反向传播起点，输出个数可调 |

「自定义函数」按钮展开四个公式（输入、输出、奖励、目标），见第六节。

训练成果（权重与随机种子）按**结构指纹**保存至应用设置，下次启动可继续训练；结构变更后旧存档自动失效，不会将尺寸不匹配的权重强行应用。

## 七、自定义函数

输入、输出、奖励、目标四个公式使用同一套小型表达式语言，其词法、语法与求值均由本项目实现，不依赖动态求值机制，因此可在离线条件下逐条比对。

| 函数 | 每步调用次数 | 默认公式 | 默认公式含义 |
| --- | --- | --- | --- |
| 输入函数 | 输入层每个位置一次 | `px/255` | 直接使用自带手写数字的原像素作为输入 |
| 输出函数 | 每个输出单元一次 | `v` | 直接使用网络输出值 |
| 奖励函数 | 每步结束时一次 | `score` | 使用计算所得得分（有目标元件时为 1 减均方误差；无目标元件时为判定对错的 0/1） |
| 目标函数 | 每个输出单元一次 | `sin(3*in(0))` | 期望输出为当前输入的正弦，用于可观察收敛的拟合任务 |

常用变量：

- 位置与尺寸：`c` `y` `x` `i`、`h` `w` `ch` `n`
- 归一化坐标：`u` `v` `cx` `cy` `rr`（左上角为 0，中心为 0 或 1，`rr` 为到中心距离）
- 当前层原值：`px`（手写数字输入为 0～255 像素，自生成输入为 -1～1 随机值）
- 输入向量：`in(k)` 与 `nin`
- 网络输出与判定：`v` `pred` `top` `p` `sum` `mean` `hit`
- 与期望输出的差距：`loss`（均方误差）、`mae`（平均绝对误差）、`score`（1 减均方误差）
- 进度：`t` 步数、`k` 示例序号、`count` 示例个数、`label` 真实数字

运算与内建函数：`+ - * / %`、比较、`&& || !`、三元 `cond ? a : b`，以及 `sin cos tan sqrt abs floor ceil round min max pow exp log clamp lerp step sign sigmoid relu` 等；「语法与函数表」列出全部条目。

公式无法解析时，程序不会中断；该项回退至默认公式，并在面板显示原因（例如「目标函数无法解析，这一步按默认公式 sin(3*in(0)) 计算」）。

## 八、计算后端与 CUDA 加速

引擎算子有两套等价实现：CPU 参考实现（`src/core/Ops.cpp`）与 CUDA 实现（`src/gpu/`）。

- 存在可用 NVIDIA 设备时默认使用 CUDA；更换机器或在无显卡机器上运行时会自动回退至 CPU。
- **批量计算使用显卡**：将多张样本按「通道＝样本」拼成一张大特征图，一次完成整个批量，连续执行「卷积 → 激活 → 池化 → 卷积 → 激活 → 池化 → 展平 → 全连接 → Softmax」。「评估全部示例」与命令行 `--mnist gpu` 均使用该路径。
- **界面可显示并切换后端**：运行循环面板中有「显卡加速：开 / 关」按钮，右侧显示当前后端（例如「CUDA · NVIDIA GeForce RTX 5060 Laptop GPU」）；关闭后，「评估全部示例」改为在 CPU 上逐张计算。两种后端的识别结论完全一致。评估结论行会注明本批计算所用后端与耗时。
- **逐层前向与训练在 CPU 上更快**：单张样本每步仅数微秒，显卡的一次内核启动开销高于该计算量，因此逐层热力图显示与循环每一步仍由 CPU 计算，以避免界面因内核启动而卡顿。
- CUDA 实现与 CPU 参考实现按**逐位一致**标准进行比对：卷积、池化、全连接、反向传播，以及全部批量算子相对逐样本调用，实测最大差为 **0**。含 `exp` 的通路（Sigmoid / Tanh / Softmax）受设备库与 MSVC 库最后 1 ulp 影响，实测最大差 1.73e-18。
- 另有「快速 float」模式：单层实测最大差 6.34e-07，整网（10000 样本）2.34e-06，适用于仅关注结论的场景。

实测（RTX 5060 Laptop，MNIST 测试集 10000 张，`nne_cli --mnist both` 一次运行所得）：

| 路径 | 耗时 | 吞吐 | 相对 CPU 逐张 |
| --- | --- | --- | --- |
| CPU 逐张（`core::runGraph`） | 2888.1 ms | 3462 张/秒 | 1× |
| CUDA 批量（double 精确，8 次内核） | 1058.8 ms | 9445 张/秒 | 2.73× |
| CUDA 批量（float 快速，套件 G-gpu 内实测） | 396.2 ms | 25241 张/秒 | 6.58× |

两条路径在 10000 张样本上的判定完全一致（9807/9807，不一致 0 个）。同一批数据中，批量处理相对单样本循环（逐张送入显卡）约快 **50×**：单样本每层均需两次主机与设备间传输，而批量仅需一次搬运。

耗时随机器负载浮动（同一操作在不同时段实测差异可在 2 倍以内），上表为同一分钟内取得的一组数据，用于观察量级。

## 十三、已知边界

- 一个图仅支持一个输入层与一个输出层，数据流为一条主链（模块可有多个上游，但仅有一条出口连线）。
- 顺序执行，不支持多分支并行。循环每一步执行一次前向（使用预训练参数或当前训练权重）；「更新权重」开启时，该步还按学习率执行反向传播；训练为逐样本随机梯度下降，不使用小批量。
- 未接入数据流的模块不参与计算，状态栏给出提示；接入主链（或点击「一键整理」）后参与计算。
- 连线为**一进一出**：将某层连接至新目标时，会同时断开其原出口与目标原入线，因此修改接线只需重新连接一次；断开后无法恢复的部分可点击「一键整理」，按左右顺序重排。
- 池化层的通道数跟随上游，不能单独增删。
- 训练与逐层前向在 CPU 上计算，批量评估在显卡上计算。逐层热力图为单张前向，显卡一次内核启动开销高于数微秒的计算量，因此不经过显卡。
- 画布布局会自动保存，下次启动继续使用；「示例网络」可恢复初始结构。
- 循环频率上限 5000 步/秒用于「全速运行」：单步约 10 ms，实际最高约 100 步/秒；填入更大值仅表示不再等待，不会提高速度。频率高于 20 步/秒时，面板显示提示。
- 模块库按「示例在前、元件在后」排列，三个示例位于顶部，无需滚动即可选择。
- 训练成果按结构指纹保存，结构变更后即失效；如需干净起点，可点击「重置神经网络」。
- 画布模块全部删除后，面板显示「画布上没有可运行的层」，逐层视图不再取值；实验循环自动停止，单步与批量评估不执行并显示回执。点击「示例网络」可恢复初始结构。
- 无头自检（`nne_cli.exe --selftest`）当前为 **96 项断言全部通过**，连续运行两次结果一致。
- 界面语言（中文 / English）由顶栏右侧按钮切换，选择记录在应用数据目录的 `lang.txt` 中。中文为原文且默认语言，因此中文文案与断言逐字未变；英文对照表位于 `tools/i18n/`（清点清单与中英对照，共 473 条），新增文案时按 `tools/i18n/README.md` 的流程处理。
- 模块名与组名是图中的数据（自带示例中为「卷积层」等，用户也可改名），切换语言不会修改存档：自带默认名按当前语言显示，用户自定义名称原样显示（见 `src/core/Names.h`）。自检使用独立存档目录（`tools\out\selftest-data`，每次运行前清空），因此不会受上次运行留下的训练图影响，也不会写入 `%APPDATA%`；`tools\verify.ps1` 的退出码因此为 0。
